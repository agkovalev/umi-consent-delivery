# Инструкция интегратору сайта

## 1. Что мы устанавливаем

Сервер сайта получает разрешённый релиз по HTTPS, проверяет подпись и сохраняет
JS/CSS у себя. Посетители загружают эти файлы с самого сайта. При недоступности
доставки установленная версия продолжает работать.

Установка библиотеки не блокирует автоматически произвольные существующие
счётчики/виджеты. Их согласие и загрузчики проверяются отдельно при интеграции.

Для сайта нужны PHP **CLI** 7.3+, cURL/OpenSSL, исходящий HTTPS и запись файлов.
PHP 7.3 — нижняя граница совместимости старых сайтов, а не рекомендация выбора версии.
В панели хостинга PHP для cron/SSH может отличаться от PHP сайта.

Получите от оператора:

| Что | Для чего |
| --- | --- |
| ZIP клиента и `.zip.sha256` | Программа установки и проверка её целостности |
| HTTPS endpoint, без завершающего `/` | Адрес сервера доставки |
| Ключ установки, 64 hex-символа | Право этого сайта получать разрешённые релизы |
| `public.pem` по доверенному каналу | Проверка подписи релизов |
| Site id и разрешённая версия | Для общения с оператором и первой активации |

Закрытый signing key вам не нужен. Ключ установки и public.pem имеют разные назначения.

## 2. Проверка ZIP и размещение файлов

Рядом с ZIP положите полученный `.sha256`. На Linux:

```sh
sha256sum -c umi-consent-delivery-client-v0.1.0.zip.sha256
```

На macOS: `shasum -a 256 -c umi-consent-delivery-client-v0.1.0.zip.sha256`.
Ожидается `OK`. Несовпадение — остановитесь и запросите архив повторно.
Checksum подтверждает целостность; ZIP и sidecar должны быть получены от доверенного оператора.
После распаковки внутри пакета можно выполнить `sha256sum -c checksums.sha256`.

Далее в примерах `/home/account` — **ваш абсолютный путь**, а `public_html` —
**ваша публичная папка**. Узнайте их в панели или у поддержки. Замените оба значения
во всех командах. Скопируйте содержимое единственной папки ZIP в `consent-delivery`:

```text
/home/account/
├── consent-delivery/         вне публичной папки
│   ├── update.php, updater.php, doctor.php, asset-urls.php
│   ├── config.example.json
│   ├── config.json           создаёте самостоятельно
│   ├── public.pem            получаете от оператора
│   ├── state/                состояние обновлений
│   └── docs/                 эти инструкции
└── public_html/
    └── assets/umi-consent/   только публичные файлы библиотеки
```

Не загружайте config.json в публичную папку, даже рядом с `.htaccess`.
Сначала создайте нужные каталоги через файловый менеджер либо SSH:

```sh
mkdir -p /home/account/consent-delivery/state
mkdir -p /home/account/public_html/assets/umi-consent
chmod 700 /home/account/consent-delivery
chmod 700 /home/account/consent-delivery/state
```

Эти права рассчитаны на запуск CLI и PHP сайта от одного пользователя хостинга.
Если пользователи различаются, настройте с поддержкой доступ веб-PHP к helper
и state/active-version через группу. Не открывайте доступ к config.json и не ставьте 777.
Если `open_basedir` исключает приватную папку, поддержку нужно попросить разрешить её чтение PHP сайта.

## 3. Конфиг

Скопируйте `config.example.json` в `config.json` и отредактируйте в защищённом
файловом менеджере или редакторе. Не вставляйте ключ в командную строку.

```json
{
  "baseUrl": "https://delivery.example.ru",
  "token": "ВСТАВЬТЕ_КЛЮЧ_УСТАНОВКИ",
  "publicKey": "/home/account/consent-delivery/public.pem",
  "stateDir": "/home/account/consent-delivery/state",
  "assetDir": "/home/account/public_html/assets/umi-consent"
}
```

`delivery.example.ru` — пример: замените его полученным endpoint. В `baseUrl`
нет пути, query string и завершающего `/`. Все файловые пути абсолютные.
Сохраните доверенный PEM без изменения содержимого/переводов строк.

```sh
chmod 600 /home/account/consent-delivery/config.json
```

Ожидается, что config.json читается только владельцем, а не другими пользователями.
Не храните его в Git, общих логах или обращениях в поддержку.

## 4. Проверка хостинга

Ниже `php` — CLI-бинарник нужной версии. В cron часто нужен полный путь,
например `/usr/bin/php`; **узнайте точный путь у своего хостинга**, не копируйте наугад.

```sh
php /home/account/consent-delivery/doctor.php
php /home/account/consent-delivery/doctor.php /home/account/consent-delivery/config.json --online --web-root /home/account/public_html
```

Первый запуск проверяет PHP и расширения. Второй — конфиг, каталоги, файловые
операции, расположение секретов, доступ к серверу, TLS и подпись манифеста.
Ожидается строка с разрешённой версией и отсутствие `FAIL`.

- `OK` — проверка пройдена.
- `WARN` — прочитайте пояснение и выполните ручную проверку. CLI не может подтвердить права веб-PHP или реальную конфигурацию web root.
- `FAIL` — исправьте причину и повторите. Код завершения команды — 1.

Диагностика не устанавливает релиз, не меняет active/highest-version и не занимает
lock обновления. Для проверки записи она создаёт и удаляет свои временные файлы.
Без `--online` сетевых запросов нет. Без `--web-root` расположение относительно публичной папки не проверяется.

### Если есть cron в панели, но нет SSH

Создайте одноразовое задание с полными путями:

```sh
/ПУТЬ/К/php /home/account/consent-delivery/doctor.php /home/account/consent-delivery/config.json --online --web-root /home/account/public_html > /home/account/consent-delivery/doctor.log 2>&1
```

Журнал находится в приватной папке. Дождитесь выполнения, прочитайте его в файловом
менеджере и удалите задание. Аналогично можно однократно выполнить install и activate,
последовательно проверяя результат. Не оставляйте задания активации повторяться.

## 5. Первоначальная установка

```sh
php /home/account/consent-delivery/update.php /home/account/consent-delivery/config.json install
```

Ожидается `0.6.0 installed; activation is separate` либо другая разрешённая версия.
В assets появляется полный каталог версии. Теперь активируйте **именно выведенную версию**:

```sh
php /home/account/consent-delivery/update.php /home/account/consent-delivery/config.json activate 0.6.0
```

Ожидается `Active: 0.6.0`. До этого шага helper в рабочий шаблон не подключайте:
без активной версии он завершится ошибкой.

## 6. Подключение к шаблону

Сохраните копию изменяемого шаблона. В PHP-шаблоне один раз получите обе ссылки:

```php
<?php
require_once '/home/account/consent-delivery/asset-urls.php';
$consentAssets = umiConsentAssetUrls('/home/account/consent-delivery/state');
?>
<link rel="stylesheet" href="<?= htmlspecialchars($consentAssets['css'], ENT_QUOTES, 'UTF-8') ?>">

<!-- Здесь сохраняется существующий window.UmiConsentConfig -->

<script defer src="<?= htmlspecialchars($consentAssets['js'], ENT_QUOTES, 'UTF-8') ?>"></script>
```

Замените прежние подключения JS/CSS библиотеки, не добавляйте вторую копию.
Конфиг согласия должен быть объявлен до JS. Не создавайте рядом второй конфиг.
Если библиотека устанавливается впервые, настройте её конфиг по документации
umi-cookie-consent и отдельно проверьте загрузчики счётчиков/виджетов.

По умолчанию helper формирует URL `/assets/umi-consent/VERSION/...`.
При другом публичном пути передайте его вторым аргументом, например
`umiConsentAssetUrls('/home/account/consent-delivery/state', '/static/consent')`.
Один вызов на HTML-ответ гарантирует согласованную пару JS/CSS.

Для UMI/XSLT ссылки нужно передать из PHP-слоя в XSLT: готового универсального
адаптера в пакете нет. Для статического HTML укажите два URL установленной версии
вручную; команда activate сама статический HTML не переписывает.

Очистите HTML-кеш CMS, если он включён. Откройте сайт в новом приватном окне:

1. Страница не выдаёт PHP-ошибку, баннер и настройки открываются.
2. В Network оба файла загружаются с сайта, со статусом 200, из одной папки версии.
3. Браузер не обращается к API доставки и не получает ключ установки.
4. Отказ сохраняется после перезагрузки; необязательные сервисы не запускаются до согласия.

При ошибке чтения helper/state верните прежние подключения и исправьте права/open_basedir.

## 7. Обновление и откат

Оператор сначала разрешает релиз вашему site id. Затем:

```sh
php /home/account/consent-delivery/update.php /home/account/consent-delivery/config.json check
php /home/account/consent-delivery/update.php /home/account/consent-delivery/config.json install
php /home/account/consent-delivery/update.php /home/account/consent-delivery/config.json activate 0.6.0
```

В последней команде замените версию на установленную новую. `check` выводит доступную
версию и запоминает максимум увиденных версий; для проверки без записи используйте doctor.
Сначала install, затем отдельное activate, после — кеш и проверка страницы.
При ошибке скачивания активная версия сохраняется.

Для отката на **ранее установленную и сохранившуюся** версию:

```sh
php /home/account/consent-delivery/update.php /home/account/consent-delivery/config.json rollback 0.5.0
```

Сеть для activate/rollback не нужна; локальные подпись и файлы проверяются повторно.
Серверный downgrade намеренно запрещён: назначение старой версии оператором не заменяет
локальный rollback. Не удаляйте старые каталоги, пока на них ссылается HTML-кеш.
Обновление файлов само по себе не повышает revision согласия.

Регулярный cron можно использовать для `check`, например раз в сутки. Результат
передавайте в существующий мониторинг хостинга; сам клиент уведомления не отправляет.
Автоматические install/activate в этом комплекте не настраиваются.

## 8. Ошибки и ключи

| Симптом | Действие |
| --- | --- |
| 401 | Уточнить у оператора, не отозван/ротирован ли ключ; заменить token в приватном конфиге |
| 403 | Попросить оператора разрешить версию нужному site id |
| 429 | Повторить позже; не запускать частый cron или параллельные установки |
| Сеть/TLS | Проверить endpoint, DNS, исходящий HTTPS и CA хостинга; не отключать TLS-проверку |
| Подпись не прошла | Остановиться, сверить PEM и источник релиза с оператором; не обходить проверку |
| Config mode | Установить 0600 и проверить владельца файла |
| Another updater | Дождаться другого процесса; не удалять lock у работающего клиента |
| Server downgrade | Использовать локальный rollback; не удалять highest-version для обхода |
| Нет активной версии | Успешно выполнить install и activate до подключения helper |

После ротации измените только token, сохраните права 0600 и повторите doctor --online.
Публичный signing PEM не меняется при обычной ротации ключа установки.
При отзыве доступа уже установленные файлы продолжают обслуживаться сайтом.

Если доступны только FTP и файловый менеджер, без CLI/cron, текущий updater на
хостинге не запускается. Интегратор может скачать и проверить релиз этим клиентом
на своей доверенной машине, загрузить полный каталог версии по SFTP/FTPS и вручную
изменить оба URL в HTML. Ключ установки при этом остаётся на машине интегратора.
Не превращайте update.php в публичный веб-установщик.
